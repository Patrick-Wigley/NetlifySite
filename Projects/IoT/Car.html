Overview

In this project I explore the use of a triaxial (3 axis) accelerometer, and an SD card module for storing large, streaming data locally. This project was insired by my final year project, where I look into alternative off-the-self industrial vibration sensors (WitMotion) and a advanced datalogger (Digital Matter Hawk-4G). Moreover, as a quick project the christmas holiday I have made my own vibration datalogger, does it compare with the industrial stuff??

What information can you infer from collecting vibration data on a car? :)

1. Setup

For this project, I am using Adafruits Triaxial Accelerometer, an MicroSD card read/write module & an Elegoo ESP32 Dev Board.

Lets get into it :)
Firstly, I began prototyping the solution on a breadboard. Both the SD & Accelerometer components use their own communication protocol - An the esp32 supports both with designated pins for certain busses.

Figure 1. Reference sheet for Elegoo ESP32 pinouts


SD Card Module
SD card module allows for synchronous reading & writing into a MicroSD card. it takes a 5v powers supply and the esp32 can supply a stable 5v through the VIN pin. The module communicates via Serial Peripheral Interface (SPI) protocol, this uses 4 busses:
  • SCK - Clock
  • CS - Chip Selector
  • MOSI - Master Out Slave In (on ESP is Controller Out Peripheral In or COPI)
  • MISO - Master In Slave Out (on ESP is Controller In Peripheral Out or CIPO)

Accelerometer Module
Adafruit have developed a brilliant 3-axis accelerometer capable of measuring frequencies from 1.56Hz - 800Hz depending on configuration of Output Data Rate (ODR) in code. The module runs at 3v with an on board regulator, therefore we can conveniently supply 3.3v straight from the esp. This module communications via I²C which supports multiple linked components. Therefore, you could use sensor fusion to increase accuracy & robustness of the readings. For this project I have just stuck with the single vib sensor. The I²C communication busses used for this project are busses are:
  • SDA - Serial Data
  • SCL - Serial Clock

Programming
There are prebuilt libraries for both SPI and I²C communications - in fact Adafruit provide an opensourced library stored in the "Adafruit_MMA8451.h" header file. And Arduino provide an opensourced SD library for SPI communication handle with SD peripherals, the developer just needs to instantiate an object of the SPIClass, configure it and use the static "SD" singleton class, passing the configuration SPIClass in and done pretty much. Takes the fun of coding away!
As regards to the logic, I simply iterate through all the existing files in SD to get the most recent iteration (n) and create a new file naming it iteration n+1 to keep track during this run. And sending a high digital signal to pin 2 on the esp lights up the onboard blue LED as a debug/informative signal, for if modules aren't being detected (the LED lit up alot during the soldering part of this project whoops) or if the SD card is full. 
VibrationCapture.cpp


/*
  Capturing vibration data & storing into SD card 
  Using:
  - Adafruit MMA8451  (I2C Comm)
  - MH-SD Card Module (SPI Comm)
*/

/* Pins & Consts */
#define P_ErrSig 2
#define DEBUG 1

/* Includes */
#include <Wire.h>
#include <Adafruit_MMA8451.h>
#include <Adafruit_Sensor.h>

#include <SPI.h>
#include <SD.h>

/* Static Vars */ 
Adafruit_MMA8451 mma = Adafruit_MMA8451();

SPIClass* vspi;
// 1MHz, MSB, MODE0 
SPISettings spiConfiguration(1000000, MSBFIRST, SPI_MODE0);
const String FILE_PREFIX = "/VR";
String file_name;

#define MISO_ALT 33

void setup() {
  Serial.begin(115200);
  if (DEBUG) delay(5000);  
  pinMode(P_ErrSig, OUTPUT);

  vspi = new SPIClass(VSPI);
  vspi->begin(SCK, MISO, MOSI,  SS);


  /* Testing Configurations */
  if (!mma.begin()) {
    // Keep err sig pulled high - Somethings not connected correctly or broken.
    Serial.println("Failed to begin accelerometer"); 
    digitalWrite(P_ErrSig, HIGH); 
    while(1);
  }
  while (!SD.begin(SS, *vspi, 1000000)) {
    // Wait for SD card to be inserted
    Serial.println("Failed to begin SD module (Is the card plugged in? You silly. Or the boards possibly broke from moisture in the air, you silly)");
    digitalWrite(P_ErrSig, HIGH); 
    delay(500);
    digitalWrite(P_ErrSig, LOW);
    delay(500);
  }
  // Else, everything is good :)
  

  /* Setup Accel */
  mma.setRange(MMA8451_RANGE_2_G);
  mma.setDataRate(MMA8451_DATARATE_100_HZ); //MMA8451_DATARATE_50_HZ


  /* Setup SD */
  // Get new files name (Prefix + str(files_count+1))
  unsigned int counter = 1;
  while (SD.exists(FILE_PREFIX + String(counter))) counter++;
  file_name = FILE_PREFIX + String(counter);


  /* Operative Information */ 
  if (DEBUG) {
    Serial.println(); Serial.println("Monitoring At");
    Serial.print("Range = "); Serial.print(2 << mma.getRange()); Serial.println("G");
    Serial.print("Using datarate option "); Serial.print(mma.getDataRate()); Serial.println(" - 100Hz");  // Hard coded - dont want to make a lookup table for the datarate codes.
  
    SD_Stats();
    Serial.println(); Serial.print("Storing triaxial acceleration data into "); Serial.println(file_name);
  }
}

void loop() {
  mma.read();
  sensors_event_t event; 
  mma.getEvent(&event);

  // Write to file
  File sd_file = SD.open(file_name, FILE_APPEND, true);
  if (sd_file) {
    String data = String(event.acceleration.x) + "," + String(event.acceleration.y) + "," + String(event.acceleration.z);
    sd_file.println(data);
    sd_file.close();
  }
  if (SD.usedBytes() > ((SD.totalBytes()-100))) // Computationally quicker then percentage
    SD_full();

}

void SD_full(){
  digitalWrite(P_ErrSig, HIGH);
  if (DEBUG) Serial.println("SD FULL");
  while (1);
}

void SD_Stats() {
  Serial.println("-=-=--= SD Details =--=-=- "); 
  Serial.print("Card Size: "); Serial.print(SD.cardSize());     Serial.print(" ("); Serial.print(SD.cardSize() / 1000000000); Serial.println("GB)");
  Serial.print("Total Bytes: "); Serial.print(SD.totalBytes()); Serial.print(" ("); Serial.print(SD.totalBytes() / 1000000000); Serial.println("GB)");
  Serial.print("Used Bytes: "); Serial.print(SD.usedBytes());   Serial.print(" ("); Serial.print(SD.usedBytes() / 1000000000); Serial.println("GB)");
  Serial.println();
  Serial.print("Card Type: "); Serial.println(SD.cardType());
  Serial.print("Num of Sectors: "); Serial.println(SD.numSectors());
  Serial.print("Sector Size: "); Serial.println(SD.sectorSize());
  Serial.println("-=-=--= ----------------- =--=-=-"); 
}

2. Prototyping


Breadboard Configuration
It is safe to test and devise a suitable configuration for the components initially before jumping straight onto the proto board. So, I pulled out my breadboard and fitted the componets, connecting SPI & I2C pinouts to the corresponding pins on the esp32

Note it is not necessary to use some of these pins, although for standardisation I used them. You could use D33 with MOSI for example, if your MOSI pin was faulty.

Inititally I was using an SD (not microSD) module. Hense the adapter. This was later swapped for a MicroSD card module

Figure 2. Breadboard Wiring & Debugging

Compiling & Uploading VibrationCapture.cpp works as expected, populating a CSV file on the microSD card with X,Y,Z acceleration records.


Working on the prototype board
From my very little experience with soldering so far, I have learned it takes a lot of patients & care. Ofcourse, concentraction & accuracy of wiring is imperative, but spending extra time doing tasks neatly & with care goes a long way.

I have got some 22AWG insulated wire, perfect for small electronic components, some proto PCB boards with non connected through-holes (think this is also called a vector board?), plug and play female connectors for interchangeability & resuse, some flux & lead-free solder, a desolder pump & a soldering iron. 360C works well for my setup, with the sharp tip for tight soldering joints (connecting wires on neighbouring through-holes) & the flat-headed tip for soldering header pins to boards.

After basic LED cicuitry practice, a few failed revisions and research for helpful tips & tricks, I got it right in the end. Tediosuly, a decent amount of time was spent making the wiring as reasonably neat as I possible, ensuring no cross talk. And best of all, it works! My multimeter displaying strong continuity for each connection was very satisfiying.
